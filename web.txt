아름다운 수프 문서¶
HTML 및 XML 파일에서 데이터를 가져오기 위한 아름다운 Soupis aPython 라이브러리입니다. 이는 여러분이 선호하는 파서와 함께 작동하여 구문 분석 트리를 탐색, 검색 및 수정하는 관용적인 방법을 제공합니다. 이는 일반적으로 프로그래머의 작업 시간 또는 며칠을 절약해 줍니다.
이 지침은 뷰티플수프 4의 모든 주요 기능을 예시와 함께 설명합니다. 라이브러리가 무엇인지, 어떻게 작동하는지, 어떻게 사용하는지, 원하는 대로 작동하게 만드는 방법, 기대에 어긋날 경우 어떻게 해야 하는지 보여드리겠습니다.
이 문서는 뷰티플수프 버전 4.15.0을 다룬다. 이 문서의 예제는 Python 3.8용으로 작성되었습니다.
BeautifulSoup 3에 대한 문서를 찾고 있을 수도 있습니다. 그렇다면 BeautifulSoup 3은 더 이상 개발되지 않으며 이에 대한 모든 지원이 2020년 12월 31일에 중단되었음을 알아야 합니다. BeautifulSoup 3과 Beautiful Soup 4의 차이점에 대해 알고 싶다면 BS4로 코드 포팅을 참조하세요.
이 문서는 Beautiful Soup 사용자에 의해 다른 언어로 번역되었습니다:
  도움 받기¶
  Beautiful Soup에 대해 질문이 있거나 문제가 발생하면 토론 그룹에 메일을 보내세요. 문제가 HTML 문서 구문 분석과 관련된 경우 해당 문서에 대해 Diagnostic() 함수가 말하는 내용을 언급해야 합니다.
  이 문서의 오류를 보고할 때 어떤 번역을 읽고 있는지 언급해 주세요.
    API 문서¶
    이 문서는 사용 설명서처럼 작성되었지만 BeautifulSoup 소스 코드에서 생성된 전통적인 API 문서도 읽을 수 있습니다. 뷰티플수프의 내부나 이 문서에서 다루지 않은 기능에 대한 자세한 내용을 알고 싶다면 API 문서를 시도해 보세요.

다음은 이 문서 전체에서 예로 사용할 HTML 문서입니다. 이상한 나라의 앨리스 이야기의 일부입니다.
Beautiful Soup을 통해 "세 자매" 문서를 실행하면 문서를 중첩된 데이터 구조로 나타내는 BeautifulSoup 개체가 제공됩니다.

뷰티플수프 설치하기¶
최신 버전의 Debian 또는 Ubuntu Linux를 사용하는 경우 시스템 패키지 관리자를 사용하여 Beautiful Soup을 설치할 수 있습니다.
$apt-get python3-bs4 설치
뷰티플수프 4는 PyPi를 통해 공개되어 있으므로, 시스템 패키저로 설치할 수 없다면 easy_installorpip로 설치하면 된다. 패키지 이름은 beautifulsoup4입니다. Python 버전에 맞는 piporeasy_install 버전을 사용하고 있는지 확인하세요(각각 pip3 및 easy_install3으로 이름이 지정될 수 있음).
$easy_installbeautifulsoup4
$pipinstallbeautifulsoup4
(BeautifulSoup 패키지는 당신이 원하는 것이 아닙니다. 그것은 이전 주요 릴리스인 Beautiful Soup 3입니다. 많은 소프트웨어가 BS3를 사용하므로 여전히 사용할 수 있지만 새 코드를 작성하는 경우 beautifulsoup4를 설치해야 합니다.)
easy_install이나 pip가 설치되어 있지 않다면 Beautiful Soup 4 소스 tarball을 다운로드하고 setup.py로 설치할 수 있습니다.
$pythonsetup.pyinstall
다른 모든 방법이 실패하더라도 Beautiful Soup 라이센스를 사용하면 전체 라이브러리를 애플리케이션과 함께 패키징할 수 있습니다. 타르볼을 다운로드하고, bs4 디렉터리를 응용 프로그램의 코드베이스에 복사하고, 전혀 설치하지 않고도 Beautiful Soup을 사용할 수 있습니다.
저는 Beautifulsoup를 개발하기 위해 Python 3.10을 사용하지만 다른 최신 버전에서도 작동할 것입니다.
  파서 설치¶
  뷰티플수프는 파이썬의 표준 라이브러리에 포함된 HTML 파서를 지원하지만, 다수의 제3자 파이썬 파서도 지원한다. 그 중 하나가 lxml 파서이다. 설정에 따라 다음 명령 중 하나를 사용하여 lxml을 설치할 수 있습니다.
  $apt-getinstallpython-lxml
  $easy_installlxml
  $pipinstalllxml
  또 다른 대안은 웹 브라우저가 수행하는 방식으로 HTML을 구문 분석하는 순수 Pythonhtml5lib 파서입니다. 설정에 따라 다음 명령 중 하나를 사용하여 html5lib를 설치할 수 있습니다.
  $apt-getinstallpython3-html5lib
  $pipinstallhtml5lib
  이 표에는 각 파서 라이브러리의 장점과 단점이 요약되어 있습니다.
  가능하다면 속도를 위해 lxml을 설치하고 사용하는 것이 좋습니다.
  문서가 유효하지 않다면, 각기 다른 파서가 그에 대한 각기 다른 뷰티풀 수프 트리를 생성한다는 점에 유의하십시오. 자세한 내용은 파서 간의 차이점을 참조하세요.
수프 만들기¶
문서를 구문 분석하려면 해당 문서를 BeautifulSoup 생성자에 전달하세요. 문자열이나 열린 파일 핸들을 전달할 수 있습니다.
먼저 문서가 유니코드로 변환되고 HTML 엔터티가 유니코드 문자로 변환됩니다.
그런 다음 Beautiful Soup은 사용 가능한 최상의 파서를 사용하여 문서를 구문 분석합니다. XML 파서를 사용하도록 특별히 지시하지 않는 한 HTML 파서를 사용합니다. (XML 구문 분석을 참조하세요.)
객체의 종류¶
Beautiful Soup은 복잡한 HTML 문서를 복잡한 Python 객체 트리로 변환합니다. 하지만 태그, 탐색 가능한 문자열, BeautifulSoup 및 Comment의 네 가지 종류의 개체만 처리하면 됩니다. 이러한 개체는 페이지를 구성하는 HTML 요소를 나타냅니다.
태그에는 문자열이 텍스트 조각으로 포함될 수 있습니다. Beautiful Soup은 NavigableString 클래스를 사용하여 다음 텍스트 조각을 포함합니다.
ANavigableString은 트리 탐색 및 트리 검색에 설명된 일부 기능도 지원한다는 점을 제외하면 Python 유니코드 문자열과 같습니다. str을 사용하여 NavigableString을 유니코드 문자열로 변환할 수 있습니다.
문자열을 그 자리에서 편집할 수는 없지만,replace_with()를 사용하여 한 문자열을 다른 문자열로 바꿀 수 있습니다:
NavigableString은 트리 탐색 및 트리 검색에 설명된 대부분의 기능을 지원하지만 전부는 아닙니다. 특히, 문자열은 아무 것도 포함할 수 없기 때문에(atag가 문자열이나 다른 태그를 포함할 수 있는 방식) 문자열은 .contents 또는.string 속성 또는 find() 메서드를 지원하지 않습니다.
Beautiful Soup 외부에서 NavigableString을 사용하려면 str()을 호출하여 일반 PythonUnicode 문자열로 바꿔야 합니다. 그렇지 않으면, Beautiful Soup 사용을 다시 마친 경우에도 문자열은 전체 Beautiful Soup 구문 분석 트리에 대한 참조를 가지고 다닐 것입니다. This is a big waste of memory.
BeautifulSoup 객체는 구문 분석된 문서 전체를 나타냅니다. 대부분의 경우 이를 Tag객체로 처리할 수 있습니다. 이는 트리 탐색 및 트리 검색에 설명된 대부분의 방법을 지원한다는 의미입니다.
태그와 마찬가지로 트리 수정에 정의된 메서드 중 하나에 BeautifulSoup 개체를 전달할 수도 있습니다. 이를 통해 두 개의 구문 분석된 문서를 결합하는 등의 작업을 수행할 수 있습니다.
BeautifulSoup 개체는 실제 HTML 또는 XML 태그와 일치하지 않으므로 이름이나 속성이 없습니다. 그러나 때로는 .name을 참조하는 것이 유용하므로(예: Tagand 및 BeautifulSoup 객체 모두에서 작동하는 코드를 작성할 때) 특별한 .name"[document]"가 지정되었습니다.
  다중값 속성¶
  HTML 4는 여러 값을 가질 수 있는 몇 가지 속성을 정의합니다. HTML 5는 그 중 몇 가지를 제거하지만 몇 가지를 더 정의합니다. 가장 일반적인 다중 값 속성은 클래스입니다(즉, 태그는 둘 이상의 CSS 클래스를 가질 수 있습니다). 기타에는 rel, rev, accept-charset, header 및 accesskey가 포함됩니다. 기본적으로 BeautifulSoup은 다중 값 속성의 값을 목록으로 저장합니다:
  태그를 다시 문자열로 변환하면 다중 값 속성의 값이 통합됩니다.
  속성이 하나 이상의 값을 갖고 있는 것처럼 보이지만 HTML 표준의 모든 버전에서 정의한 다중 값 속성이 아닌 경우 Beautiful Soup은 이를 간단한 문자열로 저장합니다:
  BeautifulSoup 생성자에 키워드 인수로 multi_valued_attributes=Nonea를 전달하여 모든 속성을 문자열로 저장하도록 강제할 수 있습니다.
  get_attribute_list를 사용하면 문자열이든 다중 값 속성 값이든 항상 목록 컨테이너의 값을 반환할 수 있습니다.
  문서를 XML로 구문 분석하는 경우 다중 값 속성이 없습니다.

  특수 문자열¶
  Tag, NavigableString 및 BeautifulSoup에는 HTML 또는 XML 파일에서 볼 수 있는 거의 모든 내용이 포함되어 있지만 몇 가지 남은 부분이 있습니다. 아마도 당신이 접하게 될 주요 내용은 Comment(댓글)입니다.
  Comment객체는 NavigableString의 특별한 유형입니다.
  그러나 HTML 문서의 일부로 나타나는 경우 주석은 특수 형식으로 표시됩니다.
    HTML 문서의 경우¶
    Beautiful Soup은 특정 HTML 태그 내부에 있는 문자열을 포함하는 몇 가지 NavigableString 하위 클래스를 정의합니다. 이렇게 하면 페이지 내에서 발견된 프로그래밍 지시문을 나타내는 문자열을 무시하여 페이지의 본문을 더 쉽게 선택할 수 있습니다. (이 클래스는 Beautiful Soup 4.9.0의 새로운 클래스이며 html5lib 파서는 이를 사용하지 않습니다.)
    내장된 CSS스타일시트를 나타내는 ANavigableString 하위 클래스입니다. 즉, 문서 구문 분석 중 &lt;style&gt; 태그 내부에서 발견된 모든 문자열입니다.
    EmbeddedJavascript를 나타내는 ANavigableString 하위 클래스입니다. 즉, 문서 구문 분석 중 &lt;script&gt; 태그 내부에서 발견된 모든 문자열입니다.
    내장된 HTML 템플릿을 나타내는 ANavigableString 하위 클래스입니다. 즉, 문서 구문 분석 중 &lt;template&gt; 태그 내부에서 발견된 모든 문자열입니다.
    XML 문서의 경우¶
    Beautiful Soup은 XML 문서에서 찾을 수 있는 특수한 유형의 문자열을 보유하는 일부 NavigableString 클래스를 정의합니다. Comment와 마찬가지로 이러한 클래스는 출력 시 문자열에 추가 항목을 추가하는 NavigableString의 하위 클래스입니다.
    XML 문서 시작 부분의 선언을 나타내는 NavigableString 하위 클래스입니다.
    XML 문서의 시작 부분 근처에서 찾을 수 있는 문서 유형 선언을 나타내는 ANavigableString 하위 클래스입니다.
    CData 섹션을 나타내는 ANavigableString 하위 클래스입니다.
    XML 처리 명령의 내용을 나타내는 ANavigableString 하위 클래스입니다.
트리 탐색하기¶
여기에 다시 "Three sisters" HTML 문서가 있습니다:
문서의 한 부분에서 다른 부분으로 이동하는 방법을 보여주기 위한 예로 이것을 사용하겠습니다.
  아래로 내려가기¶
  태그에는 문자열과 추가 태그가 포함될 수 있습니다. 이러한 요소는 태그 하위입니다. Beautifulsoup는 태그의 하위 항목을 탐색하고 반복하기 위한 다양한 속성을 제공합니다.
  문자열은 자식을 가질 수 없기 때문에 Beautifulsoup 문자열은 이러한 속성을 지원하지 않습니다.
    태그 이름을 사용하여 탐색하기¶
    구문 분석 트리를 탐색하는 가장 간단한 방법은 이름으로 태그를 찾는 것입니다. 이렇게 하려면 find() 메서드를 사용할 수 있습니다.
    편의상 원하는 태그 이름을 말하는 것은 find()(해당 이름을 가진 내장 속성이 없는 경우)와 동일합니다. &lt;head&gt; 태그를 원하면, 그냥soup.head라고 말하세요:
    이 트릭을 계속해서 사용하여 구문 분석 트리의 특정 부분을 확대할 수 있습니다. 이 코드는 &lt;body&gt; 태그 아래에 첫 번째 &lt;b&gt; 태그를 가져옵니다.
    find()(및 편의상 해당 기능)는 해당 이름의 첫 번째 태그만 제공합니다.
    모든 &lt;a&gt; 태그를 가져와야 하는 경우 find_all()을 사용할 수 있습니다.
    패턴 일치 및 필터링과 같은 보다 복잡한 작업의 경우 트리 검색에 설명된 방법을 사용할 수 있습니다.
    .contentsand.children¶
    태그의 하위 항목은.contents라는 목록에서 사용할 수 있습니다.
    BeautifulSoup 객체 자체에는 자식이 있습니다. 이 경우 &lt;html&gt; 태그는 theBeautifulSoup 객체의 자식입니다.:
    문자열에는 아무것도 포함할 수 없기 때문에 내용이 없습니다.
    목록으로 가져오는 대신 .children 생성기를 사용하여 태그의 하위 항목을 반복할 수 있습니다.
    태그의 하위 항목을 수정하려면 트리 수정에 설명된 방법을 사용하세요. the.contentslist를 직접 수정하지 마십시오. 그러면 미묘하고 발견하기 어려운 문제가 발생할 수 있습니다.

    .contents 및.children 속성은 태그의 직접 하위 항목만 고려합니다. 예를 들어 &lt;head&gt; 태그에는 단일 직계 하위 태그인 &lt;title&gt; 태그가 있습니다.

    &lt;head&gt; 태그에는 자식이 하나만 있지만 &lt;title&gt; 태그와 &lt;title&gt; 태그의 자식이라는 두 개의 하위 항목이 있습니다. BeautifulSoup 객체에는 하나의 직계 자식(&lt;html&gt; 태그)만 있지만 하위 항목은 많이 있습니다.
    .string¶
    태그에 하위 항목이 하나만 있고 해당 하위 항목이 NavigableString인 경우 하위 항목을 .string으로 사용할 수 있습니다.
    태그의 유일한 하위 태그가 다른 태그이고 해당 태그에 .string이 있는 경우 상위 태그는 하위 태그와 동일한.string을 갖는 것으로 간주됩니다.
    태그에 둘 이상의 항목이 포함되어 있으면.string이 무엇을 참조해야 하는지 명확하지 않으므로.string은 beNone으로 정의됩니다.
    .stringsandstripped_strings¶
    태그 안에 두 개 이상의 항목이 있는 경우에도 문자열을 확인할 수 있습니다. 모든 하위 문자열을 보려면 the.stringsgenerator를 사용하십시오.
    태그를 구분하는 줄바꿈과 공백도 문자열입니다. 대신 .stripped_stringsgenerator를 사용하여 추가 공백을 제거할 수 있습니다.
    여기서는 공백으로만 이루어진 문자열은 무시하고, 문자열의 시작과 끝 부분에 있는 공백을 제거한다.

  다음과 같은 간단한 문서를 생각해 보세요.
  &lt;b&gt; 태그와 &lt;c&gt; 태그는 같은 수준에 있습니다. 둘 다 같은 태그의 직계 자식입니다. 우리는 그들을 형제라고 부릅니다. 문서가 예쁘게 인쇄되면 형제 항목이 동일한 들여쓰기 수준으로 표시됩니다. 작성한 코드에서 이 관계를 사용할 수도 있습니다.
    .next_siblingand.previous_sibling¶
    .next_sibling 및.previous_sibling을 사용하여 구문 분석 트리의 동일한 수준에 있는 페이지 요소 간을 탐색할 수 있습니다.
    &lt;b&gt; 태그에는 a.next_sibling이 있지만, 트리의 동일한 수준에서 &lt;b&gt; 태그 앞에는 아무것도 없기 때문에 no.previous_sibling이 있습니다. 같은 이유로 &lt;c&gt; 태그에는 a.previous_sibling이 있지만 no.next_sibling이 있습니다.
    문자열 "text1"과 "text2"는 동일한 부모가 없기 때문에 형제가 아닙니다.
    실제 문서에서 태그의 .next_sibling 또는.previous_sibling은 일반적으로 공백이 포함된 문자열입니다. "세 자매" 문서로 돌아가서:
    첫 번째 &lt;a&gt; 태그의 .next_sibling이 두 번째 &lt;a&gt; 태그가 될 것이라고 생각할 수도 있습니다. 그러나 실제로는 문자열입니다. 첫 번째 &lt;a&gt; 태그와 두 번째 태그를 구분하는 쉼표와 줄 바꿈입니다.
    두 번째 &lt;a&gt; 태그는 쉼표 문자열의.next_sibling입니다.
    .next_siblingsand.previous_siblings¶
    .next_siblingsor.previous_siblings를 사용하여 태그의 형제를 반복할 수 있습니다.
    (속성 값으로 태그를 찾는 인수 구문이 익숙하지 않은 경우 걱정하지 마십시오. 이 내용은 나중에 키워드 인수에서 다룹니다.)
  앞뒤로 이동하기¶
  "세 자매" 문서의 시작 부분을 살펴보세요.
  HTML 파서는 이 문자열을 가져와 "&lt;html&gt; 태그 열기", "&lt;head&gt; 태그 열기", "&lt;title&gt; 태그 열기", "문자열 추가", "&lt;title&gt; 태그 닫기", "&lt;p&gt; 태그 열기" 등의 일련의 이벤트로 변환합니다. 여는 태그와 문자열이 만나는 순서를 문서 순서라고 합니다. Beautiful Soup은 문서의 요소를 문서 순서대로 검색하는 도구를 제공합니다.
    .next_elementand.previous_element¶
    문자열이나 태그의.next_element 속성은 현재 태그를 연 직후나 현재 문자열 이후에 구문 분석된 모든 항목을 가리킵니다. .next_sibling과 동일할 수도 있지만 일반적으로 크게 다릅니다.
    다음은 "세 자매" 문서의 마지막 &lt;a&gt; 태그입니다. Its.next_sibling은 문자열입니다. &lt;a&gt; 태그의 시작으로 중단된 문장의 결론입니다.
    그러나 &lt;a&gt; 태그 바로 다음에 전달된 해당 &lt;a&gt; 태그의.next_element는 해당 문장의 나머지 부분이 아닙니다. 그 안에 있는 문자열 "Tillie"입니다.
    그 이유는 원래 마크업에서 "Tillie"라는 단어가 세미콜론 앞에 나타났기 때문입니다. 파서는 &lt;a&gt; 태그, "Tillie"라는 단어, 닫는 &lt;/a&gt; 태그, 세미콜론 및 문장의 나머지 부분을 발견했습니다. 세미콜론은 &lt;a&gt; 태그와 같은 수준에 있지만 "Tillie"라는 단어가 먼저 발견되었습니다.
    .previous_element 속성은.next_element와 정반대입니다. 이는 이 태그 직전에 구문 분석된 여는 태그 또는 문자열을 가리킵니다.
    .next_elementsand.previous_elements¶
    지금쯤이면 아이디어를 얻을 수 있을 것입니다. 이러한 반복자를 사용하여 문서가 구문 분석된 대로 문서에서 앞이나 뒤로 이동할 수 있습니다.
트리 검색¶
Beautiful Soup은 구문 분석 트리를 검색하는 많은 방법을 정의하지만 모두 매우 유사합니다. 나는 가장 널리 사용되는 두 가지 방법인 find()와 find_all()을 설명하는 데 많은 시간을 할애할 것입니다. 다른 방법은 거의 동일한 인수를 사용하므로 간단히 다루겠습니다.
다시 한 번 "세 자매" 문서를 예로 사용하겠습니다.
find_all()과 같은 메소드에 필터를 전달하면 문서에서 관심 있는 부분을 확대할 수 있습니다.
  필터 종류¶
  find_all() 및 유사한 메서드에 대해 자세히 설명하기 전에 이러한 메서드에 전달할 수 있는 다양한 필터의 예를 보여주고 싶습니다. 이러한 필터는 검색 API 전반에 걸쳐 계속해서 표시됩니다. 이를 사용하여 태그 이름, 속성, 문자열 텍스트 또는 이들의 조합을 기준으로 필터링할 수 있습니다.
    문자열¶
    가장 간단한 필터는 문자열입니다. 검색 메소드에 문자열을 전달하면 Beautiful Soup은 정확한 문자열에 대해 태그 이름 일치를 수행합니다. 이 코드는 문서에서 모든 &lt;b&gt; 태그를 찾습니다.

  find_all()¶
  메소드 서명: find_all(name,attrs,recursive,string,limit,**kwargs)
  find_all() 메서드는 태그의 하위 항목을 살펴보고 필터와 일치하는 모든 하위 항목을 검색합니다. 필터 종류에서 몇 가지 예를 제시했지만 여기에 몇 가지가 더 있습니다.
  이들 중 일부는 익숙해 보이지만 일부는 새로운 것입니다. 문자열, orid에 대한 값을 전달한다는 것은 무엇을 의미합니까? find_all("p","title")이 CSS 클래스 "title"이 있는 &lt;p&gt; 태그를 찾는 이유는 무엇입니까?find_all()에 대한 인수를 살펴보겠습니다.

    이름에 대한 값이 짐승, 정규식, 목록, 함수 또는 True 값일 수 있는 필터 종류를 상기해 보세요.
    키워드 인수¶
    인식되지 않는 모든 키워드 인수는 해당 속성에 따라 태그를 일치시키는 필터로 전환됩니다.
    id라는 인수에 대한 값을 전달하면 뷰티플수프는 각 태그의 'id' 속성 값을 기준으로 필터링합니다:
    태그와 마찬가지로 문자열, 정규식, 목록, 함수 또는 True 값을 기준으로 속성을 필터링할 수 있습니다.
    href에 대한 정규식 개체를 전달하면 Beautifulsoup는 각 태그의 'href' 속성 값에 대해 패턴 일치를 수행합니다.
    valueTrue는 속성을 정의하는 모든 태그와 일치합니다. 이 코드는 anida 속성이 있는 태그를 모두 찾습니다.
    더 복잡한 일치의 경우 속성값을 유일한 인수로 사용하는 함수를 정의할 수 있습니다. 함수는 값이 일치하면 True를 반환하고 그렇지 않으면 False를 반환해야 합니다.
    다음은 hrefattribute가 정규식과 일치하지 않는 allatag를 찾는 함수입니다.
    인수 목록을 전달하면 BeautifulSoup은 해당 목록에 있는 문자열, 정규식 또는 함수에 대해 속성-값 일치를 찾습니다. 이 코드는 첫 번째 링크와 마지막 링크를 찾습니다.
    여러 키워드 인수를 전달하여 한 번에 여러 속성을 기준으로 필터링할 수 있습니다.
    HTML 5의 data-* 속성과 같은 일부 속성에는 키워드 인수의 이름으로 사용할 수 없는 이름이 있습니다.
    이러한 속성을 사전에 넣고 사전을 속성 인수로 find_all()에 전달하여 검색에 사용할 수 있습니다.
    마찬가지로, HTML의 'name' 속성을 검색하기 위해 키워드 인수를 사용할 수 없습니다. 왜냐하면 Beautiful Soup은 태그 자체의 이름을 포함하기 위해 name 인수를 사용하기 때문입니다. 대신 속성 인수에서 'name'에 값을 지정할 수 있습니다.
    CSS 클래스로 검색하기¶
    특정 CSS 클래스가 있는 태그를 검색하는 것은 매우 유용하지만 CSS 속성의 이름인 "class"는 Python에서 예약어입니다. class를 키워드 인수로 사용하면 구문 오류가 발생합니다. 뷰티플수프 4.1.2부터, 키워드 인수class_를 사용하여 CSS 클래스로 검색할 수 있습니다:
    다른 키워드 인수와 마찬가지로 클래스에 문자열, 정규식, 함수 또는 True를 전달할 수 있습니다.
    단일 태그가 해당 "클래스" 속성에 대해 여러 값을 가질 수 있다는 점을 기억하십시오. 특정 CSS 클래스와 일치하는 태그를 검색하면 해당 CSS 클래스와 일치하게 됩니다.
    class속성의 정확한 문자열 값을 검색할 수도 있습니다.
    그러나 문자열 값의 변형 검색은 작동하지 않습니다.
    class_shortcut이 없는 이전 버전의 Beautiful Soup에서는 위에서 언급한 속성 인수 트릭을 사용할 수 있습니다. "class" 값이 검색하려는 문자열(또는 정규 표현식 등)인 사전을 만듭니다.
    두 개 이상의 CSS 클래스와 동시에 일치하는 태그를 검색하려면 여기에 설명된 Tag.select()CSS 선택기 메서드를 사용하세요.
    Thestringargument¶
    string 인수를 사용하면 태그 대신 문자열을 검색할 수 있습니다. 이름 및 속성 키워드 인수와 마찬가지로 문자열, 정규식, 함수, 목록 또는 True 값을 전달할 수 있습니다. 다음은 몇 가지 예입니다.
    태그 검색에서 문자열 인수를 사용하면 뷰티플수프는 문자열이 문자열 값과 일치하는 모든 태그를 찾을 것이다. 이 코드는 문자열이 "Elsie"인 &lt;a&gt; 태그를 찾습니다.
    문자열 인수는 Beautiful Soup 4.4.0의 새로운 기능입니다. 이전 버전에서는 텍스트라고 불렀습니다.
    Thelimitargument¶
    find_all()은 필터와 일치하는 모든 태그와 문자열을 반환합니다. 문서가 큰 경우 시간이 걸릴 수 있습니다. 모든 결과가 필요하지 않은 경우 제한 수를 전달할 수 있습니다. 이는 SQL의 LIMIT 키워드와 동일하게 작동합니다. 이는 Beautiful Soup에게 특정 숫자를 찾은 후에는 결과 수집을 중지하도록 지시합니다.
    "세 자매" 문서에는 세 개의 링크가 있지만 이 코드는 처음 두 개만 찾습니다.
    Therecursiveargument¶
    기본적으로 mytag.find_all()은 mytag의 모든 하위 항목, 즉 하위 항목, 하위 항목의 하위 항목 등을 검사합니다. directchildren만 고려하려면 inrecursive=False를 전달하면 됩니다. 여기서 차이점을 확인하세요.
    문서의 해당 부분은 다음과 같습니다.
    &lt;title&gt; 태그는 &lt;html&gt; 태그 아래에 있지만 &lt;html&gt; 태그 바로 아래에 있는 것은 아닙니다. &lt;head&gt; 태그가 방해가 됩니다. Beautiful Soup은 &lt;html&gt; 태그의 모든 자손을 볼 수 있을 때 &lt;title&gt; 태그를 찾지만, recursive=False가 &lt;html&gt; 태그의 직계 자식으로 제한하면 아무것도 찾지 못합니다.
    Beautiful Soup은 많은 트리 검색 방법(아래에서 설명)을 제공하며 대부분 find_all():name,attrs,string,limit 및 속성 키워드 인수와 동일한 인수를 사용합니다. 그러나 재귀적 인수는 find_all() 및 find() 메서드에만 해당됩니다. find_parents()와 같은 메서드에 recursive=False를 전달하는 것은 별로 유용하지 않습니다.
  태그를 호출하는 것은 find_all()을 호출하는 것과 같습니다¶
  편의상 BeautifulSoup객체나 Tag객체를 함수로 호출하는 것은 find_all()을 호출하는 것과 동일합니다(찾고 있는 태그 이름이 내장된 메소드가 없는 경우). 다음 두 코드 줄은 동일합니다.
  다음 두 줄도 동일합니다.
  찾다()¶
  메소드 서명: find(name,attrs,recursive,string,**kwargs)
  find_all() 메서드는 결과를 찾기 위해 전체 문서를 스캔하지만 때로는 하나의 결과만 찾고 싶을 때도 있습니다. 문서에 &lt;body&gt; 태그가 하나만 있다는 것을 알고 있다면 더 많은 것을 찾기 위해 전체 문서를 스캔하는 것은 시간 낭비입니다. find_all을 호출할 때마다 inlimit=1을 전달하는 대신 find() 메서드를 사용할 수 있습니다. 다음 두 코드 줄은 거의 동일합니다.
  유일한 차이점은 find_all()은 단일 결과가 포함된 목록을 반환하고 find()는 결과만 반환한다는 것입니다.
  find_all()이 아무것도 찾을 수 없으면 빈 목록을 반환합니다. Iffind()가 아무것도 찾을 수 없으면 None을 반환합니다.
  태그 이름을 사용하여 탐색에서 나온soup.head.title 트릭을 기억하시나요? 이 트릭은 find()를 반복적으로 호출하여 작동합니다.
  find_parents()와 find_parent()¶
  메소드 서명: find_parents(name,attrs,string,limit,**kwargs)
  메소드 서명: find_parent(name,attrs,string,**kwargs)
  나는 find_all()과find()를 다루는데 많은 시간을 보냈습니다. Beautiful Soup API는 트리를 검색하기 위한 10가지 다른 방법을 정의하지만 두려워하지 마세요. 이들 메소드 중 5개는 기본적으로 find_all()과 동일하고 나머지 5개는 기본적으로 find()와 동일합니다. 유일한 차이점은 트리의 한 부분에서 다른 부분으로 이동하는 방식에 있습니다.
  먼저 find_parents()와find_parent()를 고려해 봅시다. find_all()과 find()는 태그의 자손을 보면서 트리 아래로 작업한다는 것을 기억하세요. 이 메서드는 그 반대입니다. 즉, 태그(또는 문자열)의 부모를 보면서 트리 위로 작업합니다. "세 딸" 문서에 깊이 묻혀 있는 문자열부터 시작해 보겠습니다.
  세 개의 &lt;a&gt; 태그 중 하나는 문자열 검색의 직접적인 상위 항목이므로 검색에서 이를 찾습니다. 세 개의 &lt;p&gt; 태그 중 하나는 문자열의 간접적인 상위(조상)이며 검색 결과도 마찬가지입니다. 문서 어딘가에 CSS 클래스 "title"이 있는 &lt;p&gt; 태그가 있지만 이 문자열의 부모 중 하나가 아니므로 find_parents()로 찾을 수 없습니다.
  앞서 언급한 find_parent()와 find_parents(), 그리고 .parent 및.parents 속성 사이에 유사점이 있음을 눈치챘을 것입니다. 이러한 검색 방법은 실제로 .parents 속성을 사용하여 모든 상위 항목(필터링되지 않음)을 반복하고 제공된 필터와 비교하여 일치하는지 확인합니다.
  find_next_siblings()와find_next_sibling()¶
  메소드 서명: find_next_siblings(name,attrs,string,limit,**kwargs)
  메소드 서명: find_next_sibling(name,attrs,string,**kwargs)
  이러한 메서드는 트리에 있는 요소의 나머지 형제 항목에 대해 .next_siblingstoiterate를 사용합니다. find_next_siblings() 메서드는 일치하는 모든 형제를 반환하고, find_next_sibling()은 첫 번째 형제만 반환합니다.
  find_previous_siblings()와find_previous_sibling()¶
  메소드 서명: find_previous_siblings(name,attrs,string,limit,**kwargs)
  메소드 서명: find_previous_sibling(name,attrs,string,**kwargs)
  이러한 메서드는 .previous_sibling을 사용하여 트리에서 앞에 있는 요소의 형제를 반복합니다. find_previous_siblings() 메서드는 일치하는 모든 형제를 반환하고, find_previous_sibling()은 첫 번째 형제만 반환합니다.
  find_all_next()와find_next()¶
  메소드 서명: find_all_next(name,attrs,string,limit,**kwargs)
  메소드 서명: find_next(name,attrs,string,**kwargs)
  이러한 메서드는 .next_element를 사용하여 문서에서 그 뒤에 오는 모든 태그와 문자열을 반복합니다. find_all_next() 메서드는 일치하는 항목을 모두 반환하고, find_next()는 첫 번째 일치 항목만 반환합니다.
  첫 번째 예에서는 우리가 시작한 &lt;a&gt; 태그 내에 포함되어 있음에도 불구하고 문자열 "Elsie"가 표시되었습니다. 두 번째 예에서는 문서의 마지막 &lt;p&gt; 태그가 우리가 시작한 &lt;a&gt; 태그와 트리의 동일한 부분에 있지 않더라도 표시되었습니다. 이러한 방법의 경우 중요한 것은 요소가 필터와 일치하고 나중에 문서 문서 순서에 표시된다는 것입니다.
  find_all_previous()와find_previous()¶
  메소드 서명: find_all_previous(name,attrs,string,limit,**kwargs)
  메소드 서명: find_previous(name,attrs,string,**kwargs)
  이러한 메서드는 .previous_elements를 사용하여 문서에서 그 앞에 있는 태그와 문자열을 반복합니다. find_all_previous() 메서드는 일치하는 모든 항목을 반환하고, find_previous()는 첫 번째 일치 항목만 반환합니다.
  find_all_previous("p")에 대한 호출은 문서의 첫 번째 문단(class="title"인 문단)을 찾았지만 두 번째 문단, 즉 우리가 시작한 &lt;a&gt; 태그를 포함하는 &lt;p&gt; 태그도 찾습니다. 이것은 별로 놀라운 일이 아닙니다. 우리는 문서 순서에서 처음보다 먼저 나타나는 모든 태그를 보고 있습니다. &lt;a&gt; 태그를 포함하는 &lt;p&gt; 태그는 해당 태그가 포함하는 &lt;a&gt; 태그 앞에 표시되어야 합니다.

    고급 수프 체 기능¶
    Soup Sieve는 select() 및 select_one() 메서드 이상의 실질적인 API를 제공하며, TagorBeautifulSoup의.css 속성을 통해 해당 API의 대부분에 액세스할 수 있습니다. 다음은 지원되는 방법 목록입니다. 전체 문서는 수프 체 문서를 참조하세요.
    iselect() 메서드는 select()와 동일하게 작동하지만 목록 대신 생성기를 반환합니다.
    closest() 메소드는 Beautiful Soup의 find_parent() 메소드와 유사하게 CSS 선택자와 일치하는 주어진 태그의 가장 가까운 부모를 반환합니다.
    match() 메서드는 특정 태그가 선택기와 일치하는지 여부에 따라 부울 값을 반환합니다.
    filter() 메소드는 선택기와 일치하는 태그의 직계 하위 항목의 하위 집합을 반환합니다.
    escape() 메서드는 유효하지 않은 CSS 식별자를 이스케이프합니다.

    CSS 선택기 지원의 역사¶
    뷰티플수프 4.12.0에는 .css 속성이 추가되었습니다. 이전에는.select() 및.select_one() 편의 메서드만 지원되었습니다.

트리 수정¶
Beautiful Soup의 가장 큰 장점은 구문 분석 트리를 검색하는 것이지만, 트리를 수정하고 변경 사항을 새로운 HTML 또는 XML 문서로 작성할 수도 있습니다.
  태그 이름 및 속성 변경¶
  앞서 inTag.attrs에 대해 다루었지만 반복할 필요가 있습니다. 태그 이름을 바꾸고, 해당 속성 값을 변경하고, 새 속성을 추가하고, 속성을 삭제할 수 있습니다.
  .string 수정¶
  태그의.string 속성을 새 문자열로 설정하면 태그 내용이 해당 문자열로 대체됩니다.
  주의하세요. 태그에 다른 태그가 포함되어 있으면 해당 태그와 해당 콘텐츠가 모두 삭제됩니다.
  추가()¶
  Tag.append()를 사용하여 태그의 내용을 추가할 수 있습니다. Python 목록에서.append()를 호출하는 것과 동일하게 작동합니다.
  Tag.append()는 새로 추가된 요소를 반환합니다.
  연장하다()¶
  뷰티플수프 4.7.0부터 Tag는 목록의 모든 요소를 ​​Tag에 순서대로 추가하는 .extend()라는 메서드도 지원합니다.
  Tag.extend()는 추가된 요소 목록을 반환합니다.
  NavigableString()과.new_tag()¶
  문서에 문자열을 추가해야 하는 경우 문제 없습니다. Python 문자열을 append()에 전달하거나 NavigableString 생성자를 호출할 수 있습니다.
  주석이나 NavigableString의 다른 하위 클래스를 생성하려면 생성자를 호출하면 됩니다.
  (뷰티플수프 4.4.0의 새로운 기능입니다.)
  완전히 새로운 태그를 생성해야 한다면 어떻게 해야 할까요? 가장 좋은 해결책은 팩토리 메소드 BeautifulSoup.new tag()를 호출하는 것입니다.
  첫 번째 인수인 태그 이름만 필수입니다.
  (``new_tag``에 대한 ``string`` 인수는 Beautiful Soup 4.13.0에서 도입되었습니다.)
  삽입 메소드는 새로 삽입된 요소를 반환하므로 한 단계로 요소를 생성, 삽입 및 가져올 수 있습니다.
  끼워 넣다()¶
  Tag.insert()는 새로운 요소가 반드시 상위 요소의.contents 끝에 올 필요가 없다는 점을 제외하면 Tag.append()와 같습니다. Python 목록의 .insert()와 유사하게 원하는 숫자 위치에 삽입됩니다.
  Tag.insert()에 두 개 이상의 요소를 전달할 수 있습니다. 제공한 숫자 위치부터 시작하여 모든 요소가 삽입됩니다.
  Tag.insert()는 새로 삽입된 요소의 목록을 반환합니다.
  insert_before()와insert_after()¶
  insert_before() 메서드는 구문 분석 트리의 다른 항목 바로 앞에 태그나 문자열을 삽입합니다.
  insert_after() 메서드는 구문 분석 트리의 다른 항목 바로 뒤에 태그나 문자열을 삽입합니다.
  두 메서드 모두 새로 삽입된 요소 목록을 반환합니다.
  분명한()¶
  Tag.clear()는 태그 내용을 제거합니다.
  발췌()¶
  PageElement.extract()는 트리에서 태그나 문자열을 제거합니다. 추출된 태그 또는 문자열을 반환합니다.
  이 시점에서 당신은 효과적으로 두 개의 구문 분석 트리를 갖게 됩니다. 하나는 문서를 구문 분석하는 데 사용한 BeautifulSoup 개체에 뿌리를 두고 있고, 다른 하나는 추출된 태그에 뿌리를 두고 있습니다. 추출한 요소의 하위 요소에 대해 callextract()를 계속할 수 있습니다.
  분해()¶
  Tag.decompose()는 트리에서 태그를 제거한 다음 해당 태그와 해당 내용을 완전히 삭제합니다.
  분해된TagorNavigableString의 동작은 정의되지 않았으며 어떤 용도로도 사용해서는 안 됩니다. 무언가가 분해되었는지 확실하지 않다면 its.decomposedproperty(Beautiful Soup 4.9.0의 새로운 기능)를 확인하세요.
  교체_with()¶
  PageElement.replace_with()는 트리에서 태그나 문자열을 추출한 다음 이를 선택한 하나 이상의 태그나 문자열로 바꿉니다.
  replacement_with()는 대체된 태그나 문자열을 반환하므로 이를 검사하거나 트리의 다른 부분에 다시 추가할 수 있습니다.
  여러 인수를 대체_with()에 전달하는 기능은 뷰티플수프 4.10.0에 새로 추가되었습니다.
  포장하다()¶
  PageElement.wrap()은 지정한 Tag 객체의 요소를 래핑합니다. 새 래퍼를 반환합니다.
  이 방법은 뷰티플수프 4.0.5에 새로 추가되었습니다.
  풀다()¶
  Tag.unwrap()은 ofwrap()과 반대입니다. 태그를 해당 태그 내부의 내용으로 대체합니다. 마크업을 제거하는 데 좋습니다.
  replace_with()와 마찬가지로 unwrap()은 대체된 태그를 반환합니다.
  매끄러운()¶
  구문 분석 트리를 수정하는 여러 메서드를 호출한 후 두 개 이상의 NavigableString 객체가 서로 나란히 있게 될 수 있습니다. Beautiful Soup에는 이에 대한 문제가 없지만 새로 구문 분석된 문서에서는 발생할 수 없기 때문에 다음과 같은 동작을 기대하지 않을 수 있습니다.
  Tag.smooth()를 호출하여 인접한 문자열을 통합하여 구문 분석 트리를 정리할 수 있습니다.
  이 방법은 뷰티플수프 4.8.0에 새로 추가되었습니다.
Output¶
  예쁘게 인쇄하기¶
  prettiify() 메소드는 뷰티플수프 구문 분석 트리를 각 태그와 각 문자열에 대해 별도의 줄을 사용하여 멋진 형식의 유니코드 문자열로 변환합니다.
  최상위 BeautifulSoup 개체 또는 해당Tag 개체에서 prettiify()를 호출할 수 있습니다.
  공백(개행 형식)을 추가하므로 prettify()는 HTML 문서의 의미를 변경하므로 형식을 다시 지정하는 데 사용해서는 안 됩니다. prettify()의 목표는 작업하는 문서의 구조를 시각적으로 이해하도록 돕는 것입니다.
  예쁘지 않은 인쇄¶

  encode()를 호출하여 바이트 문자열을 얻고 decode()를 호출하여 유니코드를 얻을 수도 있습니다.

  get_text()¶
  문서나 태그 안에 사람이 읽을 수 있는 텍스트만 원하는 경우 get_text() 메서드를 사용할 수 있습니다. 문서 또는 태그 아래의 모든 텍스트를 단일 유니코드 문자열로 반환합니다.
  텍스트 비트를 함께 결합하는 데 사용할 문자열을 지정할 수 있습니다.
  Beautiful Soup에게 각 텍스트 비트의 시작과 끝에서 공백을 제거하도록 지시할 수 있습니다.
  하지만 그 시점에서는 대신 the.stripped_stringsgenerator를 사용하고 텍스트를 직접 처리할 수 있습니다.
  Beautiful Soup 버전 4.9.0부터 lxml이나 html.parser를 사용 중일 때 &lt;script&gt;, &lt;style&gt;, &lt;template&gt; 태그의 내용은 일반적으로 '텍스트'로 간주되지 않습니다. 왜냐하면 이러한 태그는 사람이 볼 수 있는 페이지 내용의 일부가 아니기 때문입니다.
  Beautiful Soup 버전 4.10.0부터 NavigableString 객체에 대해 get_text(),.strings 또는 .stripped_strings를 호출할 수 있습니다. 객체 자체를 반환하거나 아무것도 반환하지 않으므로 이를 수행하는 유일한 이유는 혼합 목록을 반복할 때입니다.
  Beautiful Soup 버전 4.13.0부터는 NavigableString 객체에서 .string을 호출할 수 있습니다. 객체 자체를 반환하므로 이를 수행하는 유일한 이유는 혼합 목록을 반복할 때입니다.
사용할 파서 지정하기¶
일부 HTML을 구문 분석해야 하는 경우 마크업을 BeautifulSoup 생성자에 덤프하면 아마 괜찮을 것입니다. BeautifulSoup은 당신을 위해 파서를 선택하고 데이터를 구문 분석합니다. 그러나 어떤 파서가 사용되는지 변경하기 위해 생성자에 전달할 수 있는 몇 가지 추가 인수가 있습니다.
BeautifulSoup 생성자에 대한 첫 번째 인수는 구문 분석하려는 마크업의 소스인 문자열 또는 열린 파일 핸들입니다. 두 번째 인수는 마크업을 어떻게 구문 분석할지입니다.
아무것도 지정하지 않으면 설치된 최고의 HTML 파서를 얻게 됩니다. Beautiful Soup은 lxml의 파서가 가장 좋고, 그 다음이 html5lib, 그 다음이 Python의 내장 파서입니다. 다음 중 하나를 지정하여 이를 재정의할 수 있습니다.
파서 설치 섹션에서는 지원되는 파서와 대조됩니다.
설치되지 않은 파서를 요청하면 뷰티플수프는 당신이 알 수 없는 규칙에 따라 문서를 부주의하게 파싱하지 않도록 예외를 발생시킬 것이다. 예를 들어 현재 유일하게 지원되는 XML 파서는 lxml입니다. lxml이 설치되어 있지 않으면 XML 파서를 요청해도 결과가 나오지 않으며 "lxml"을 요청해도 작동하지 않습니다.
  파서의 차이점¶
  Beautiful Soup은 여러 다른 파서에 동일한 인터페이스를 제공하지만 각 파서는 다릅니다. 서로 다른 파서는 동일한 문서에서 서로 다른 구문 분석 트리를 생성합니다. HTML 파서와 XML 파서의 가장 큰 차이점은 다음과 같습니다. 다음은 Python과 함께 제공되는 구문 분석기를 사용하여 HTML로 구문 분석된 짧은 문서입니다.
  독립형 &lt;b/&gt; ​​태그는 유효한 HTML이 아니기 때문에 html.parser는 이를 &lt;b&gt;&lt;/b&gt; 태그 쌍으로 바꿉니다.
  다음은 XML로 구문 분석된 동일한 문서입니다(이를 실행하려면 lxml이 설치되어 있어야 합니다). 독립형 &lt;b/&gt; ​​태그는 단독으로 남겨지고 문서에는 XML 선언이 제공됩니다.
  HTML 파서 간에도 차이점이 있습니다. BeautifulSoup에 완벽하게 구성된 HTML 문서를 제공하면 이러한 차이점은 중요하지 않습니다. 한 파서는 다른 파서보다 빠르지만 모두 원본 HTML 문서와 똑같은 데이터 구조를 제공합니다.
  그러나 문서가 완벽하게 구성되지 않은 경우 파서마다 다른 결과가 나타납니다. 다음은 lxml의 HTML 파서를 사용하여 파싱된 짧고 유효하지 않은 문서입니다. &lt;a&gt; 태그는 &lt;body&gt; 및 &lt;html&gt; 태그로 묶이고 매달린 &lt;/p&gt; 태그는 무시됩니다.
  다음은 html5lib를 사용하여 구문 분석된 동일한 문서입니다.
  매달린 &lt;/p&gt; 태그를 무시하는 대신 html5lib는 이를 여는 &lt;p&gt; 태그와 쌍으로 연결합니다. html5lib는 빈 &lt;head&gt; 태그도 추가합니다. lxml은 신경 쓰지 않았습니다.
  다음은 Python의 내장 HTMLparser로 구문 분석된 동일한 문서입니다:
  lxml과 마찬가지로 이 구문 분석기는 닫는 &lt;/p&gt; 태그를 무시합니다. html5lib 또는 lxml과 달리 이 파서는 &lt;html&gt; 또는 &lt;body&gt; 태그를 추가하여 올바른 형식의 HTML 문서를 생성하려고 시도하지 않습니다.
  "&lt;a&gt;&lt;/p&gt;" 문서가 유효하지 않기 때문에 이러한 기술 중 어느 것도 문서를 처리하는 '올바른' 방법이 아닙니다. html5lib 파서는 HTML5 표준의 일부인 기술을 사용하므로 '올바른' 방식이라는 최고의 주장을 갖고 있지만 세 가지 기술 모두 합법적입니다.
  파서 간의 차이점은 스크립트에 영향을 줄 수 있습니다. 스크립트를 다른 사람에게 배포하거나 여러 컴퓨터에서 실행할 계획이라면 BeautifulSoup 생성자에 구문 분석기를 지정해야 합니다. 그러면 사용자가 문서를 구문 분석하는 방식과 다르게 문서를 구문 분석할 가능성이 줄어듭니다.
Encodings¶
모든 HTML 또는 XML 문서는 ASCII 또는 UTF-8과 같은 특정 인코딩으로 작성됩니다. 하지만 해당 문서를 Beautiful Soup에 로드하면 해당 문서가 유니코드로 변환되었음을 알 수 있습니다.
그것은 마술이 아닙니다. (물론 좋겠죠.) Beautiful Soup은 Unicode라는 하위 라이브러리인 Dammit를 사용하여 문서의 인코딩을 감지하고 이를 유니코드로 변환합니다. 자동 감지된 인코딩은 BeautifulSoup 개체의.original_encoding 속성으로 사용할 수 있습니다.
만약.original_encoding이None이라면, 이는 문서가 Beautiful Soup에 전달되었을 때 이미 유니코드였음을 의미합니다:
유니코드, 젠장, 대부분의 경우 정확하게 추측하지만 때로는 실수를 하기도 합니다. 때때로 정확하게 추측하지만, 문서를 바이트 단위로 검색한 후에만 매우 오랜 시간이 걸립니다. 문서의 인코딩을 미리 알고 있다면 이를 from_encoding으로 BeautifulSoup 생성자에 전달하여 실수와 지연을 피할 수 있습니다.
다음은 ISO-8859-8로 작성된 문서입니다. 문서가 너무 짧아서 유니코드, Dammit이 문서에 대한 잠금을 얻을 수 없고 ISO-8859-7로 잘못 식별합니다.
올바른from_encoding을 전달하여 이 문제를 해결할 수 있습니다.
올바른 인코딩이 무엇인지 모르지만 Unicode, Dammit이 잘못 추측하고 있다는 것을 알고 있다면 asexclude_encodings에 잘못된 추측을 전달할 수 있습니다.

  출력 인코딩¶
  Beautiful Soup에서 출력 문서를 작성하면 입력 문서가 처음부터 UTF-8이 아니더라도 UTF-8 문서를 얻게 됩니다. 다음은 Latin-1 인코딩으로 작성된 문서입니다.
  문서가 이제 UTF-8이라는 사실을 반영하기 위해 &lt;meta&gt; 태그가 다시 작성되었습니다.
  UTF-8을 원하지 않으면 prettiify()에 인코딩을 전달할 수 있습니다.
  마치 Python 문자열인 것처럼 BeautifulSoup 객체나 수프의 모든 요소에 대해 encode()를 호출할 수도 있습니다.
  선택한 인코딩으로 표현할 수 없는 모든 문자는 숫자 XML 엔터티 참조로 변환됩니다. 다음은 유니코드 문자 SNOWMAN을 포함하는 문서입니다.

  유니코드, 젠장¶
  Beautiful Soup을 사용하지 않고도 Unicode, Dammit를 사용할 수 있습니다. 알 수 없는 인코딩의 데이터가 있고 이를 유니코드로 만들고 싶을 때마다 유용합니다.
  Unicode, Dammit의 추측은 Python 라이브러리 charset-normalizer, chardet, orcchardet 중 하나를 설치하면 훨씬 더 정확해질 것입니다. 유니코드에 더 많은 데이터를 제공할수록 젠장, 더 정확하게 추측할 것입니다. 인코딩이 무엇인지 의심스러우면 목록으로 전달할 수 있습니다.
  유니코드, Dammit에는 Beautiful Soup이 사용하지 않는 두 가지 특별한 기능이 있습니다.
    둥근 인용문¶
    유니코드, Dammit를 사용하여 Microsoft 스마트 인용문을 HTML 또는 XMLentities로 변환할 수 있습니다.
    Microsoft 스마트 따옴표를 ASCII 따옴표로 변환할 수도 있습니다.
    이 기능이 유용하기를 바라지만, 뷰티플수프는 이 기능을 사용하지 않습니다. Beautiful Soup은 Microsoft 스마트 따옴표를 다른 모든 문자와 함께 유니코드 문자로 변환하는 기본 동작을 선호합니다.
    일관성 없는 인코딩¶
    때로는 문서가 대부분 UTF-8로 되어 있지만 Microsoft 스마트 따옴표와 같은 Windows-1252 문자가 포함되어 있는 경우도 있습니다. 웹사이트에 여러 소스의 데이터가 포함되어 있으면 이런 일이 발생할 수 있습니다. UnicodeDammit.detwingle()을 사용하여 이러한 문서를 pureUTF-8로 바꿀 수 있습니다. 간단한 예는 다음과 같습니다.
    이 문서는 엉망입니다. 눈사람은 UTF-8이고 따옴표는 Windows-1252입니다. 눈사람이나 따옴표를 표시할 수 있지만 둘 다 표시할 수는 없습니다.
    문서를 UTF-8로 디코딩하면 UnicodeDecodeError가 발생하고 Windows-1252로 디코딩하면 횡설수설이 발생합니다. 다행스럽게도 UnicodeDammit.detwingle()은 문자열을 순수 UTF-8로 변환하여 이를 유니코드로 디코딩하고 눈사람과 따옴표를 동시에 표시할 수 있게 해줍니다.
    UnicodeDammit.detwingle()은 UTF-8에 내장된 Windows-1252(또는 그 반대)를 처리하는 방법만 알고 있지만 이것이 가장 일반적인 경우입니다.
    데이터를 BeautifulSoup 또는 UnicodeDammit 생성자에 전달하기 전에 데이터에서 UnicodeDammit.detwingle()을 호출하는 방법을 알아야 합니다. Beautiful Soup은 문서가 무엇이든 단일 인코딩을 갖는다고 가정합니다. UTF-8과 Windows-1252를 모두 포함하는 문서를 전달하면 전체 문서가 Windows-1252라고 생각할 가능성이 높으며 문서는 "Ilikesnowmen!"처럼 보일 것입니다.
    UnicodeDammit.detwingle()은 뷰티플수프 4.1.0의 새로운 기능입니다.
