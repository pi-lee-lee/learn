윈도우(MSYS2/Clang) 및 리눅스 환경에서 프로그램의 생사를 결정하는 핵심 표준 시그널(SIG) 종류 요약 리스트입니다 [방법 1].
터미널이나 디버거(F5) 로그를 분석할 때 직관적으로 스캔하기 좋도록 발생 원인과 함께 분류했습니다.

------------------------------
## 🚨 1. 하드웨어/메모리 오류로 즉사하는 시그널 (C++ catch 불가)
CPU나 운영체제가 "더 이상 프로세스를 실행할 수 없다"고 판단하여 강제로 처형하는 시그널입니다.

* SIGSEGV (Segmentation Fault)
* 원인: 널 포인터 참조(nullptr), 보호된 가상 메모리 페이지 무단 침범, 배열 범위를 심하게 초과한 메모리 훼손.
* SIGFPE (Floating Point Exception)
* 원인: 정수를 0으로 나누는 산술 연산 오류 (Divide by Zero), 숫자의 표현 범위를 초과하는 오버플로우.
* SIGILL (Illegal Instruction)
* 원인: 메모리가 쓰레기 데이터로 오염되어 CPU가 해석할 수 없는 기계어 명령을 만났을 때, 혹은 지원하지 않는 CPU 가속 명령을 강제 실행했을 때.
* SIGBUS (Bus Error)
* 원인: 메모리 주소 자체의 물리적 정렬 규격을 위반했거나, 물리적으로 손상된 하드웨어 영역에 접근했을 때.

------------------------------
## 🛑 2. 프로그램 자체 모순이나 자살로 터지는 시그널
외부 요인이 아니라 C++ 런타임 엔진이나 프로세스 내부에서 스스로 문제를 감지하고 중단시켰을 때 발생합니다.

* SIGABRT (Abort)
* 원인: 던진 예외(throw)를 받아주는 catch문이 코드 전체에 단 하나도 없을 때 (std::terminate 호출), 혹은 동적 메모리를 이중 해제(Double Free)했을 때 스스로 자살.
* SIGSYS (Bad System Call)
* 원인: 운영체제 커널에 존재하지 않거나, 보안상 금지된 시스템 명령을 프로세스가 강제로 호출하려고 했을 때.

------------------------------
## 💻 3. 외부 사용자/시스템 제어로 발생하는 시그널
사용자가 키보드로 강제 중단 명령을 내리거나, 운영체제가 프로세스 관리를 위해 전송하는 신호입니다.

* SIGINT (Interrupt)
* 원인: 사용자가 터미널에서 Ctrl + C를 눌러 프로그램을 정상 종료/인터럽트 시켰을 때. [1] 
* SIGTERM (Terminate)
* 원인: 운영체제나 작업 관리자가 "이제 정상적으로 종료해라" 하고 보내는 정중한 종료 신호 (정리 작업 후 종료 가능). [2] 
* SIGKILL (Kill)
* 원인: 말을 듣지 않는 프로그램을 강제 종료(작업 끝내기)할 때 보내는 절대적인 사살 신호 (정리 작업 불가능, 즉시 소멸). [3] 
* SIGQUIT (Quit)
* 원인: 사용자가 Ctrl + \ 등을 눌러 프로그램을 종료시키면서, 당시 메모리 상태 파일(Core Dump)을 디스크에 남기라고 명령할 때.

------------------------------
## 💡 4. 자원 제어 및 프로세스 통신용 시그널

* SIGPIPE (Broken Pipe)
* 원인: 데이터를 받아줄 상대방 프로그램(파이프/소켓)이 이미 종료되었는데, 내 프로그램이 눈치 없이 계속 데이터를 밀어 넣으려고 할 때.
* SIGCHLD (Child Status Changed)
* 원인: 내 프로그램이 만든 서브 프로세스(자식 스레드/프로세스)가 종료되었거나 멈췄다고 부모에게 알릴 때.

------------------------------
